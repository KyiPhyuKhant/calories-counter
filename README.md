# Calorie Counter

An iOS-first React Native app built with Expo, Expo Router, and strict TypeScript.
The app currently contains a welcome screen and local SQLite infrastructure.
It does not require an account, server, or network connection to store data.

## Development

Use Node.js 24 LTS (or newer) and npm. Database tests use Node's built-in SQLite.

```sh
npm ci
npm start
```

For the iOS simulator, install Xcode and an iOS simulator runtime, then run:

```sh
npm run ios
```

For a physical device, run `npm start` and open the QR code with a compatible
Expo Go installation on the same network. Expo Go must support this project's
Expo SDK version. Check https://expo.dev/go for available builds; iOS App Store
availability can differ from simulator builds. If no compatible physical iOS
Expo Go build is available, a development build will be needed.

## Validation

```sh
npm run typecheck
npm run lint
npm test
npx expo install --check
npx expo export --platform ios
```

## Structure

- `src/app/`: Expo Router route entries and root navigation layout.
- `src/screens/`: Screen content, kept separate from navigation.
- `src/theme/`: Shared colors and spacing.
- `src/data/`: Database initialization, versioned migrations, typed repositories,
  and the provider that makes repositories available with `useRepositories()`.
- `tests/`: Real SQLite verification of migrations and repository behavior.
- `app.json`: Expo configuration.

Native `ios/` and `android/` directories are generated by Expo when needed and
are ignored. Keep local secrets in ignored `.env` files. Variables prefixed
with `EXPO_PUBLIC_` are bundled into the app and must never contain secrets.

## Local database

`calories-counter.db` is created in Expo SQLite's default app-local directory.
Startup enables WAL and foreign keys, then applies ordered migrations inside a
transaction using `PRAGMA user_version`. New schema changes must append a
migration; do not edit migrations already released. Initialization errors block
the app and offer a retry without deleting existing data.

There is one local profile. UUIDs identify records; food nutrition is expressed
per 100 grams, portions in grams, height in centimeters, and weight in kilograms.
Repository timestamps are normalized to UTC ISO strings. Diary entries and
planned meals copy the food name and nutrition when created. Catalog edits or
deletions preserve those snapshots. Plans are never counted as consumed entries.
Profile deletion is restricted while related records exist.

Tests execute the production migration SQL and repository queries through a
Node SQLite adapter. They do not exercise Expo's native bridge or simulator UI.
